How to tune the flywheels

The four numbers go to the Control Hub's own velocity controller (RUN_USING_ENCODER), exactly as flywheel.java runs it. Do it in this order:

  1. Direction. Open loop 0.3 on each wheel. If it spins the wrong way, tick reversed.
  2. F (feed-forward: power per ticks/s). Run the Feed-forward sweep, press Use sweep F, then FIRST start for a first P and I, and Write. With F right the wheel already sits close to target with P alone.
  3. P (push back against error). Run a step from 0 to your shooting speed. Raise P until the rise stops getting faster; back off if it overshoots or never settles.
  4. I (removes a steady offset) — only if steps settle consistently above or below target. D (damps overshoot) — usually 0 on a flywheel.
  5. Recovery. Kick (synthetic) to search, then real shots to accept. The Recovery by gain set table below lines every set you tried up side by side.

If the wheel is at full power for the whole rise, no gain makes it faster — the motor is the limit. The verdict under each step is a rule of thumb, not a measurement.

Step trials — compare gains

Every step you run lands here with the gains it ran on, plotted on top of the others. Tick the ones to compare; Use loads that trial's gains back into the wheel's boxes. Kept in this browser (last 40).

Shots and disturbances

With a wheel in VEL mode and inside its band for 0.3 s (badge armed), any drop out of the band is logged: dip depth, time to the bottom, and time until it is back in the band — the time the shooter is not ready after a shot. Kick is a synthetic disturbance (motor output cut for a few ms); it is repeatable but is not a real ball, so accept gains on real shots.

Recovery by gain set

Every shot and kick seen from this browser, grouped by the gains that were on the wheel. Lower back at speed = the next shot can fire sooner. Do not call a winner below n = 5 per set, and alternate sets (A, B, A, B…) — the battery sags as you go. Green = lowest median with n ≥ 5.

The shooting sequence

This runs the gate logic of shooter.java with the values below, fed by the shipped intake exactly as TeleOp feeds it:

  1. Wait until both wheels are within the entry band of their target.
  2. Open the gate and run the intake forward.
  3. Keep it open while it has been open less than the minimum open time, or while both wheels are still inside the wider hold band (a ball hitting the wheel dips it — the hold band stops that dip from slamming the gate on the ball).
  4. Close and go back to 1.

Not modelled: aiming and the shooting zone (the turrets stay where they are). Needs the gate's open and close positions marked on the Turrets & servos tab first.

Turrets

The turrets are positional servos, so there is no PID to tune — only the mapping from angle to servo position that turret.java uses: pos = center ± deg / (servoRange × grB / grA). Find center (turret straight ahead), check reversed (+45° must turn to the robot's left, counter-clockwise from above), then verify the ratio by pointing at ±90° and measuring. Wrong ratio → aim error grows with angle. Offset is where the turret pivot sits relative to the robot's pose center (inches, x forward, y left) — measure it with a tape.

Gate and scoopula

Both are currently 0 / 0 in shipped code (gate.openPos/closePos, scoopula.scoopPos/unscoopPos). Move the servo until it is where it belongs, then mark it.

Turret limits and start position

Do this with the wiring done. For each turret: jog it one way until the wires are as far as they may go and press Mark limit for that side; jog it back the other way and mark the other side. Then put it where it should sit at the start of a match and press Mark start. While tracking, the shipped turret never goes past a limit: when the target would carry it past one, it turns a full turn back the other way (if that still fits) instead. The jog buttons here are the only ones allowed past the marked limits; everything else on this dashboard is held inside them. Start is commanded when the turret is built at OpMode INIT. Nothing ships until you export (Export tab).

Intake motor direction

If the two intake motors fight each other (rollers turn opposite ways, the intake buzzes or stalls, both currents high), one of them is wired or mounted the other way. Run each motor alone and watch which way its roller turns. Every button runs the intake direction with the flags below applied, exactly as Intake.java applies them.

  1. Left only: does that roller pull a piece in? If not, tick left reversed.
  2. Right only: same for the right roller; tick right reversed if it pushes out.
  3. Both: they should now pull together, with no fighting, and current about the same on each side.
  4. If both pull the right way but Intake on the Intake & color tab spits pieces out, tick reverse both instead of the two motor boxes.

Ticks apply live (even while a motor is running) and are restored when the OpMode stops. Ship them from the Export tab. Keep this page open: the watchdog stops everything after 30 s with no web client.

Run any motor by hub and port

Raw open-loop power on one motor port. Every direction flag is ignored: positive power is the port's own forward. Use it to find which port a motor is on, whether it is wired, and which way it turns. One port runs at a time; starting one stops every other mechanism on this dashboard, and any other motion command stops it.

Control Hub ports 0–3 are the drive motors (sm0–sm3). Put the robot on blocks before running them, or it will drive.

A port with nothing configured is still driven, through the hub's motor controller. Ticks and velocity are only meaningful when an encoder is plugged into that port. Keep this page open: the watchdog stops everything after 30 s with no web client.

Shooting regression

Find the flywheel speed that scores from several distances, then fit ticks/s = c0 + c1·d (+ c2·d² + c3·d³) per wheel. d is the same distance Turret aims with: turret pivot (mount offset from the Turrets tab) to the hive, from the Pinpoint pose.

  1. Pick the alliance and hive, check the pose (set it if the Pinpoint was power-cycled), turn on Aim turrets.
  2. At one spot: set a wheel's speed, Spin, shoot (Shoot once, or feed by hand), adjust until it scores.
  3. Record that wheel. Move to another distance and repeat. Spread the spots over the range you shoot from.
  4. Pick linear or polynomial, check the curve and residuals, then Save fit, and on the laptop run the export command at the bottom.
